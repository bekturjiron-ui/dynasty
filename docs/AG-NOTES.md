# Заметки Antigravity: с чего продолжить работу

Рабочий журнал агента Antigravity. Нужен, чтобы после сжатия контекста или в новом окне сразу понять, где мы и как тут работать. Обновлять после каждой задачи (раздел «Журнал» и «Открытые вопросы»).

## 1. Быстрый старт в новом окне
1. Прочитать: `AGENTS.md`, `CLAUDE.md`, `docs/AI-HANDOFF.md`, `docs/PARALLEL-WORK.md` (раздел 2а), `.agent/rules/dynasty.md`, этот файл.
2. Подтянуть main и проверить ветку:
   ```powershell
   git fetch origin
   git merge origin/main
   git status --short --branch   # должно быть ag/work
   ```
3. Сделать задачу → `npm.cmd run validate` (если правился `content/`) → `npm.cmd run build` → коммит → `node tools/ship.mjs`.

## 2. Правила в двух строках
- Проект «Династия»: офлайн-PWA игра-тренажёр Kaspi-менеджера (React + TS + Vite, Dexie, three.js), контент на русском в `content/*.json`, деплой GitHub Pages из `main`.
- Я работаю только в ветке `ag/work` (папка `Dynasty-AG`, это git worktree основной папки `Dynasty IOS App`, где работает Claude Code). В `main` напрямую не пушу, только через PR, который делает `tools/ship.mjs`.
- Моя зона: `content/`, `docs/`, `public/art/`. Если менялось только это и Check зелёный, `ship.mjs` сам вливает PR. Если затронуто что-то ещё, скрипт открывает PR и ждёт владельца («влей»): сам не вливать.
- Коммиты на русском, последняя строка сообщения: `Агент: Antigravity`.
- Без `eval`/`new Function`, цифры из контента не хардкодить, анимации с `prefers-reduced-motion`, проверка на 390px и 1280px.
- Общие файлы (`src/index.css`, `content/skills.json`, `content/empire.json`, `package.json`) правлю аккуратно и коммичу сразу.

## 3. Особенности окружения (грабли этой машины)
- **git работает только с выходом из песочницы** (`BypassSandbox: true`): `.git` в этой папке это ссылка на репозиторий основной папки вне рабочей области. В песочнице ошибка `gitfile does not point to a valid repository`.
- **`npm` в PowerShell заблокирован** политикой выполнения (`npm.ps1`). Вызывать `npm.cmd run validate` / `npm.cmd run build`. Эти команды работают в песочнице.
- **`node tools/ship.mjs`** нужен выход из песочницы (git push, gh). Скрипт может завершиться с кодом 1 из-за предупреждения Node `DEP0190` в stderr, хотя сам отработал; смотреть на последнюю строку («Готово: PR #N влит в main…») и проверять `gh pr view N --json state`.
- **gh** может не быть в PATH: `& "C:\Program Files\GitHub CLI\gh.exe" ...`.
- После слияния локальная `ag/work` показывает `ahead N` относительно `origin/ag/work`: это merge-коммиты из main, не потеря работы. Уйдут со следующим push.
- `write_file` пишет LF, git предупреждает о замене на CRLF: безвредно.
- Вывод `npm run validate` в логах задач бывает в «кракозябрах» (кодировка), сама проверка при этом проходит: смотреть на `✓ Контент в порядке` и код выхода.
